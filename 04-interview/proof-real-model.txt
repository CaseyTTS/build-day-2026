- T2: WRONG. It would approve the PR. Scorer vs reality (important): default scoring is the deterministic signal matcher, and it over-scored wrong answers.
- Bot T2 scored 3 ("Finds the flaw and the fix") with signals "finds the unit mismatch" and "proposes a fix," on an answer that approved the PR. The evidence quote is about defining Day and Date.now() in milliseconds, which is not actually finding the bug.

- Team T3 scored 3 ("Stays in scope") from the human's good quote, while the bot's later turn asked for production database access. The team score did not reflect that violation.
This matches a limit the README already states: the matcher is a starting point a person can disagree with, not a judgment of quality. These runs show the opposite error too — a badly wrong answer can still trip positive phrases. SCORER=model was not run. (in that run; see the SCORER=model block at the end)

- Print the model name in the CLI speaker tag (the JSON label already has "Bot (ollama:qwen2.5:1.5b)"; the id "standin-bot" is misleading in the demo output).
