This is evidence for the recommended threshold, not a claim that 0.60 is a universal default.

Quality assessment:
Retrieval: 4/5 at the documented default 0.12. Access control worked: finance-close.md never appeared when the caller lacked the finance group, and it ranked first (0.696) when the group was present. The one FAIL is a threshold miss, not an access-control leak: with groups=everyone the restricted doc was excluded, but expenses.md scored 0.559, which is well above 0.12, so eval treated it as a retrieved source. The official code already warns that 0.12 is for the mock. Real nomic-embed-text similarities for even weak neighbors here were ~0.38-0.56.

Answer quality (qwen2.5:1.5b, temperature 0):
- VPN first check: correct (laptop clock / certs). No [1] citation even though the system prompt asks to "Cite like [1]".
- SEV1 with engineering access: FAILED. The generator returned only "[1]", not the actual answer ("Page the incident commander for every SEV1"). Retrieval was right; generation was not.
- SEV1 without engineering access: "I don't know." Correct refusal. The code's hard refuse path (no hits >= MIN_SCORE) did not fire, because vpn.md scored 0.509; the model itself refused based on the context, which is good.
- Software purchases: "procurement" — correct and short, again no citation.
- Accruals without finance: "I don't know." Correct, even though expenses.md was retrieved. So the official eval FAIL is retrieval-only; the ask path still answered honestly.
- Accruals with finance: "The accruals are posted on the second business day." Correct. No [1] citation.

No malformed JSON (this path reads chat content as plain text, not JSON). No 60s timeout. Index + asks all ran.

Validation / fallback:
- Access filter before rank worked.
- The MIN_SCORE refuse string "I don't know from the documents you can access." was not used on the official 0.12 run, because every ask had neighbors above 0.12. Two refuses came from the model instead.
- There is no check that a generated answer is more than a bare citation, so "[1]" was accepted as the SEV1 answer.

Recommended code fixes (described only, not applied):
- Make RAG_MIN_SCORE required-to-tune when RAG_PROVIDER is not mock, or ship a documented starting point per embedding model. On this corpus, 0.60 made eval 5/5 without dropping a true hit (lowest true top-1 was 0.644; the false top-1 was 0.559). That margin is tight and would need re-checking on a larger doc set.
- After a real-model answer, append the same "Sources: [1] ..." footer the mock path already prints, and reject or retry answers that are only a citation marker.
- Tighten the generator prompt so a citation must accompany a full sentence.
- Optionally cap context to neighbors within a score gap of the top hit, so a 0.828 vpn chunk is not mixed with a 0.389 expenses chunk.
